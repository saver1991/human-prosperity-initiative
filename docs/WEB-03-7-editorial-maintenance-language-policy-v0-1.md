# WEB-03.7 — Editorial maintenance, versioning, language and safe feedback V0.1

**Date:** 12 November 2026 · **Policy:** source-locked editorial governance, not a claim that HPI has appointed staff or automatic bilingual coverage.

## Version and evidence rules

Each materially changing scientific claim needs the original source, period, geography, unit, denominator, methodological limitations, a dated correction record and a visible supersession pointer. **Preserve historical files/URLs.** Correct the current editorial summary rather than silently rewriting the original publication. Do not combine Newham 78% DWP 2023/24 household model, 86% expenditure metric and 62% GB national survey. Treat HPI-B-01 participant outcome as unknown.

Release chronology is editorial, stored on [first-party Updates](/updates), not web analytics or measured beneficiary impact. A merged GitHub issue is not proof of an external institution's approval. Maintain a source-linked change log under reviewed PRs, with regression tests for canonical routes, affected claims and stable deep links.

## Maintenance process

**Proposed roles, not appointed people:** source/research owner validates research citations; site editor maintains plain-language routes and updates; accessibility tester verifies real assistive-technology acceptance; privacy/controller and legal reviewer review their own factual obligations. No human role may be reported as staffed without explicit actual acceptance.

- On each content PR: link source issue, affected public routes, facts, contradictions, original document, rollback and expected date of review.
- On monthly editorial review: identify stale titles, broken sources, outdated legal/publication claims, unsupported numerical comparisons and translations. Keep the current external review state explicit.
- On significant correction: date and label the current summary, link preserved historical version and primary-source proof; withdraw prominently if licence, safety or validity requires it.
- If affected communities are later legitimately engaged, use an ethically permitted route with safeguarding; public GitHub is **never** a private complaints or case-record inbox.

## Language and accessibility

English is the primary maintained public editorial language. Existing Italian charter and responsible-tools text are translations, not a promise the entire site is bilingual. New translations require a named reviewer, source version mapping, translation accuracy assessment (especially legal/statistical units), `hreflang` only when the full translated page exists, and an editorial revisit when source changes. Do not automatically machine-translate binding legal notices or invent local community coverage. Further language expansion is conditional on actual user needs and lawful local context.

## Privacy-safe feedback

Only public non-sensitive source corrections through documented open-source channels are possible now. No contact mailbox, user accounts, cookies banner, analytics instrumentation, testimonial collection or newsletter form is introduced by WEB-03.7. Whether analytics are lawful and useful is a later decision **after** verified provider storage and privacy audit. No future feature is claimed as deployed.
